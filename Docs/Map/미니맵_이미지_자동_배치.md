# 미니맵 이미지 자동 배치

M 키로 지도를 열면 `MapView`가 `Resources/UI/MapRooms`의 Sprite를 읽고 방 JSON의 점유 청크에 맞춰 UI Image를 생성한다. 현재는 제작된 리전 1의 A01~A06 이미지 6개가 들어 있다.

## 이름과 파일 위치

예: `Assets/Resources/UI/MapRooms/Room_A04_minimap.png`

`_minimap` 접미사를 제거한 `Room_A04`가 `MapRoomData.json`의 `Id`와 일치해야 한다. 접미사 없이 `Room_A04.png`로 두어도 된다. 대소문자는 구분한다. 이미지 이름에 좌표나 출입구 정보를 넣지 않으며, 실제 배치는 JSON이 결정한다.

새 방의 JSON을 등록하고 같은 이름의 Sprite 이미지를 추가하면 별도의 방 모양 프리팹 연결 없이 표시된다. 이미지를 추가하거나 교체한 뒤 Unity 임포트를 마치고 플레이를 다시 시작한다. 이미지가 없는 방은 생성하지 않는다. 같은 ID를 가진 이미지가 둘이면 경고한다.

## 크기와 좌표

- 기준은 청크당 250×250 UI 단위다. 화면 안에 들어가도록 방 전체를 같은 비율로 축소한다.
- 위치는 점유 청크의 최소 X·Y에 청크 크기를 곱한다.
- 크기는 점유 청크의 가로·세로 전체 범위로 계산한다. 예를 들어 A02는 500×500, A03은 500×250이다.
- L자 방도 전체 사각형 캔버스를 유지하고 빈 청크는 투명하게 둔다.
- 이미지와 데이터 영역의 가로세로 비율이 맞지 않으면 오류를 표시하고 해당 방은 건너뛴다.
- 원점은 모든 방에 공통으로 적용되므로 A03 상단과 A04 하단 등 다른 방향의 통로도 일치한다.

## 이미지 Import 설정

현재 포함된 PNG의 설정은 다음과 같다.

- Texture Type: Sprite (2D and UI)
- Sprite Mode: Single
- Mesh Type: Full Rect
- Pixels Per Unit: 250
- Generate Mip Maps: 끔
- Compression: None
- Wrap Mode: Clamp

투명 영역을 잘라내거나 Tight Mesh로 바꾸지 않는다. 이미지는 기존 시안 PNG와 동일한 원본이다.

## 현재 표시 동작

현재 리전에 속한 방 이미지만 활성화한다. 리전이 바뀌면 기존 객체를 다시 사용하며 해당 리전의 이미지가 없으면 비어 있는 지도가 된다. M 키로 닫았다 열어도 같은 ViewModel의 방을 중복 생성하지 않는다. 방 이미지 색감은 유지하고 현재 방에만 약한 녹색 강조를 적용한다.

이번 변경은 이미지 자동 로드·배치에 한정된다. 미발견 지형 숨김, 히든 발견 표시, 지도 드래그·사용자 확대, 방 이름 텍스트와 상세 패널은 별도 기능이다.

## 주요 구현

- `Assets/Scripts/UI/MapView.cs`: 이름→ID 매칭, Sprite 로드, 청크 배치, 리전 전환 및 화면 맞춤.
- `Assets/Scripts/UI/MapRoomView.cs`: 원본 이미지 색감 유지와 현재 방 강조.
- `Assets/Resources/UI/PopupUI/Map.prefab`: 자동 로드 폴더와 250단위 청크 설정.
