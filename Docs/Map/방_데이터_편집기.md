# 방 데이터 편집기

Unity 메뉴 **Tools > Map > Room Data Editor**에서 연다.

## 기본 사용

1. 왼쪽에서 방을 선택하거나 **방 추가**를 누른다.
2. 방 ID, 표시 이름, 지역 ID를 지정한다. 등록된 지역 목록에서 선택할 수도 있다.
3. 청크 격자의 빈 칸을 클릭하면 선택 방의 점유 청크에 추가되고, 다시 클릭하면 제거된다.
4. 필요하면 보상 ID, 히든 ID, 출입구 ID와 연결 대상 방 ID를 입력한다.
5. **데이터 검사**로 오류를 확인한 뒤 **저장**한다.

**출입구 추가**를 누르면 출입구 ID와 대상 방 ID의 초깃값을 채운다. `Room_A01`에서는 `Room_A01_Exit_01`과 `Room_A02`가 들어간다. 출입구 ID는 같은 방의 기존 ID와 겹치지 않는 번호를 사용하며, 대상 방은 항상 소속 방 ID의 끝 숫자에 1을 더한 값이다. 두 번째 출입구를 추가해도 대상 방을 자동으로 그다음 방까지 넘기지는 않는다. 모든 값은 직접 수정할 수 있다.

실제 연결 여부나 인접한 좌표는 추론하지 않으며 반대편 방에도 자동 추가하지 않는다. 방 ID 끝에 숫자가 없으면 대상 방은 비워 둔다. 자동 입력한 다음 방이 실제로 없으면 저장 검사에서 알려 주므로 올바른 대상 방으로 수정한다.

**이전·다음 방 출입구 자동 추가**는 선택 방에 이전 번호와 다음 번호의 방을 함께 등록한다. 예를 들어 `Room_A02`에서는 `Room_A01`, `Room_A03`을 대상으로 출입구 두 개를 추가하고 각각 중복되지 않는 출입구 ID를 부여한다. 실제 방 목록에 없는 대상과 이미 연결된 대상은 건너뛴다. 기존 출입구는 변경하거나 삭제하지 않으며, 대상 방 쪽 출입구는 자동으로 만들지 않는다. 결과를 직접 수정·삭제할 수 있고 Ctrl+Z로 되돌릴 수 있다. JSON에는 **저장**을 눌러 반영한다.

격자는 위쪽이 +Y이며 모든 리전이 같은 월드 청크 좌표를 공유한다. 청록색 ●는 선택 방이고, 다른 방은 리전별 색상 ■로 표시한다. 빨간색 !는 여러 방이 겹친 좌표다. 마우스를 올리면 해당 좌표를 점유한 모든 방의 리전·ID·이름을 확인할 수 있다. 리전을 바꿔 편집해도 이전 리전의 방은 계속 보이며, 다른 방이 점유한 칸은 추가할 수 없다. 기존에 겹친 칸은 해당 방을 선택한 뒤 클릭하면 선택 방에서만 제거된다.

## 넓은 격자 탐색

- 상단 **격자 크게 보기**를 켜면 오른쪽 영역을 격자로 넓게 사용한다. 끄면 기본 정보와 보상·히든·출입구 편집 화면으로 돌아간다.
- 격자에는 가로·세로 스크롤바가 있다. 휠은 세로, Shift+휠은 가로, 마우스 가운데 버튼 드래그는 양방향 이동이다. 격자 바깥에서 휠을 굴리면 상세 정보 전체를 스크롤한다.
- **확대 / 축소**로 칸 크기를, **격자 표시 높이**로 기본 모드의 표시 영역을 조절한다. 축 좌표는 화면 가장자리에 고정되어 스크롤 중에도 보인다.
- **탐색 범위**의 기본값은 중심 ±32청크(65×65칸)이고 ±256청크까지 넓힐 수 있다. **격자 중심**에 원하는 좌표를 입력하면 먼 위치로 이동한다.
- **선택 방으로**를 누르면 선택 방의 첫 청크 좌표로 돌아간다. 좌표 목록에서도 값을 직접 입력할 수 있다.

복제하면 이름과 지역을 복사하고 새 방 ID를 만든다. 겹치는 좌표와 중복 게임 요소를 만들지 않도록 청크·보상·히든·출입구 목록은 비워 둔다. 새 방에는 청크를 하나 이상 지정해야 저장할 수 있다.

Ctrl+Z / Ctrl+Y로 편집을 되돌리거나 다시 적용할 수 있다. 저장 전 변경은 스크립트 리로드에도 유지되며, 저장하지 않고 창을 닫으면 Unity가 저장 여부를 묻는다. **다시 불러오기**는 미저장 편집을 버리므로 확인 후 실행한다.

## 저장과 검증

- 저장 대상은 `Assets/Resources/JsonOutput/MapRoomData.json`이다. 기존 런타임 데이터 형식을 사용한다.
- 방 ID 중복, 미등록 지역, 빈 청크, 모든 리전 간 청크 중복, 빈/중복 보상·히든 ID, 잘못된 출입구 연결을 검사한다.
- 리전이 달라도 같은 청크 좌표를 사용할 수 없다. 수동 좌표 입력으로 겹침을 만들었더라도 저장 검사가 막는다. 같은 방 안에서 보상과 히든 ID를 중복으로 등록할 수 없다.
- 저장 직전 파일이 외부에서 변경된 경우 덮어쓰지 않는다. 편집 중인 값과 외부 변경을 비교한 뒤 다시 불러와 편집한다.
- 저장 때마다 이전 JSON을 `Library/MapRoomEditorBackups`에 백업한다. Library를 삭제하면 백업도 사라지므로 장기 보관은 Git을 사용한다.
- 플레이 중에는 저장할 수 없다. 게임의 데이터 캐시는 플레이를 다시 시작해야 갱신된다.

## 편집 범위

이 도구는 방 정의를 작성한다. 실제 월드 오브젝트, 지도 방 이미지, 히든 발견 트리거를 자동으로 만들지 않는다.

방 ID를 바꾸거나 삭제하면 지도 프리팹 `Assets/Resources/UI/PopupUI/Map.prefab`의 `_roomShapes`, 텔레포트 데이터의 `RevealRoomIds`, 다른 방의 출입구 참조도 확인해야 한다. 출입구 참조는 이 편집기의 저장 검사로 잡지만 지도 프리팹과 텔레포트 참조는 자동으로 수정하지 않는다.

현재 `JsonConverter/ExcelFiles`에는 방 데이터 엑셀이 없다. 추후 방 데이터를 엑셀에서도 생성하면 변환기가 JSON을 덮어쓸 수 있으므로 작성 원본을 한쪽으로 통일해야 한다.

## Unity에서 확인할 항목

1. 기존 방들이 로드되고 기존의 좌표 겹침은 빨간색으로 표시되는지 확인한다.
2. 새 방을 만들고 격자 칸을 추가·제거한 뒤 Undo/Redo를 확인한다.
3. 리전이 다른 방도 격자에 보이고, 기존 점유 칸 추가가 막히며, 수동으로 겹친 좌표나 잘못된 출입구 대상으로 저장이 거부되는지 확인한다.
4. 새 방의 청크를 지정하고 저장한 뒤 JSON 재로드와 백업 생성을 확인한다.
5. 미저장 상태에서 스크립트 리로드 및 창 닫기의 저장/취소/버리기를 확인한다.
6. 테스트 방을 제거한 뒤 기존 데이터가 유지되는지 확인한다.
7. 격자 크게 보기, 가로·세로 스크롤, 가운데 버튼 드래그, 확대·축소를 확인한다. 스크롤 후 빈 칸을 클릭했을 때 표시된 좌표가 추가되는지 확인한다.
